# 多能源站导航信息架构与验收规范

## 1. 改造目标

形成两条语义清晰的信息架构链路：“项目/园区 → 供能站房类型 → 物理站房实例（可选） → 站内功能”和“项目/园区 → 配用能系统 → 系统内功能”。左侧菜单只用于综合总览、供能站房与配用能系统选择；内容区顶部右侧根据当前关联层级明确显示“项目工作区”或“能源对象工作区”，再提供总览/运行、值班、分析、AI优化、诊断五类功能；配置作为独立项目工具，不与业务对象并列，也不继承站房上下文。

本次不改变 PLC、BFF 控制边界和现场写入逻辑。

## 2. 信息架构

| 层级 | 位置 | 职责 | 当前入口 |
| --- | --- | --- | --- |
| 项目/园区 | 顶部项目选择器 | 切换项目上下文并保留 `siteId` | 项目选择器 |
| 综合总览 | 左侧“全局” | 跨站运行结论和站点对比 | `/dashboard` |
| 供能站房 | 左侧“供能站房” | 冷冻站、空压站、锅炉房等具有明确物理边界的供能设施 | 对应站房类型首页 |
| 物理站房实例 | 左侧供能站房类型的第二级 | 同一项目内的冷冻站 A/B、空压站 1/2 等真实实例；未登记时保持类型级导航 | `stationId` 关联的站房首页 |
| 配用能系统 | 左侧“配用能系统” | 电力监控、空调末端等配能或用能侧业务系统，不作为物理站房计数 | 对应系统首页 |
| 对象内功能 | 顶部二级导航左侧 | 站房或系统专用页面显示当前对象已有功能；公共模块只保留当前页面路径，避免与右侧工作区重复 | 冷冻站工艺总览、系统孪生等 |
| 项目工作区 | 顶部二级导航右侧 | 未关联具体能源对象时，提供项目总览及跨站业务功能 | 综合总览、项目级公共模块 |
| 能源对象工作区 | 顶部二级导航右侧 | 运行、值班、分析、AI优化、诊断，并携带当前关联站房或配用能系统 | 对象内功能与兼容的公共模块 |
| 项目工具 | 顶部二级导航最右 | 参数、子系统接入、知识库，作用于当前 `siteId` | 项目配置 |

900px 以下不把工作区硬塞入顶部；同一组入口进入移动抽屉，并保持不少于 44px 的触控目标。

“系统孪生”属于冷冻站内部功能，不作为业务对象与冷冻站、空压站、锅炉房并列。

### 2.1 对象语义与实例层级

- “供能站房”表示具有明确工程空间、设备边界和运行责任的物理设施；冷冻站、空压站、锅炉房属于此组。
- “配用能系统”表示配电、计量、末端用能或分布式控制范围；电力监控、空调末端属于此组。配用能系统不是物理站房，不得用“站房数量”统计，也不得为了导航整齐伪造默认站房。
- 已发布的物理站房实例必须嵌套在匹配的供能站房类型下，以“类型 → 实例”两级呈现；实例不得与冷冻站、空压站等类型并列，也不得在多个父类型下重复出现。
- 当前 `stationId`/`stationInstances[]` 合同只表达物理站房身份。若后续需要为电力监控或空调末端登记多个业务范围，应先扩展明确的子系统实例合同，不能直接把配用能系统改称物理站房。

### 2.2 完整功能清单与可发现性

工作区一级入口不能只显示模块名称。桌面端应显示子功能数量与展开箭头，点击后在浮层中完整呈现二级功能；移动端使用抽屉内手风琴，同一时刻只展开一组。一级入口只负责展开，不同时承担默认页跳转，避免用户无法判断点击结果。

| 工作区 | 完整二级功能 | 默认入口 | 数量规则 |
| --- | --- | --- | --- |
| 总览 / 运行 | 项目工作区显示项目总览；关联能源对象后显示该对象已接入的站内/系统内功能 | 项目级为 `/dashboard`；关联对象时为该对象首页 | 随当前关联层级动态计算 |
| 值班 | 告警中心、操作日志、工单管理 | `/alarms` | 3；任意关联对象可进入，数据仍为项目级未筛选 |
| 分析 | 趋势分析、能耗分析、能效分析、能耗抄表、性能报告、历史数据 | `/trend-analysis` | 冷冻站 6；其他对象显示“尚未接入” |
| AI优化 | AI优化总览、优化建议 / 影子验证 | `/ai-overview` | 冷冻站 2；其他对象显示“尚未接入” |
| 诊断 | 设备总览、视频监控、环境工况、运行诊断 | `/devices` | 冷冻站 4；其他对象仅保留项目级视频监控 1 |
| 项目配置 | 子系统配置中心、能源参数、知识库 | `/config-center` | 3；与当前 `siteId` 关联，不携带 `station` 或 `stationId` |

左侧站房卡片使用稳定的“站房能力摘要”，例如冷冻站显示“工艺 / 系统 / 孪生 / 日志”，空压站显示“压力 / 流量 / 单耗 / 设备”。不得再用“1项”代表一个页面入口，因为页面入口数量不等于站房实际能力数量。

进入具体物理站房后，顶部站内导航和右侧工作区数量只统计真正支持该 `stationId` 的页面。已知 `resolveStationRuntimeBindingMode=unsupported` 的类型级页面不得继续携带实例参数形成可点击入口；冷冻站实例当前运行 1 项、AI 1 项、诊断 2 项，分析实例筛选未接入。用户可点击左侧父类型“冷冻站”清除 `stationId`，再访问系统总览、系统孪生、冷站日志及类型级分析，不能先显示 4/6/2/4 项可用、点击后才进入作用域阻断页。

桌面浮层采用普通按钮与链接：`Enter`、`Space` 展开，`Tab` 自然遍历，`Escape` 关闭并把焦点还给触发器，点击外部关闭。移动端手风琴的分类按钮和子链接均不得小于 44px；第一次 `Escape` 收起已展开分组，第二次关闭抽屉。

### 2.3 页面作用域策略

`station=<subsystemType>` 是导航关联上下文，不是已生效的后端筛选参数。壳层必须同时显示“关联对象”和“数据范围”，并根据中央路由策略决定是否允许页面挂载。

| 页面类型 | 当前路由 | 数据范围文案 | 非兼容对象行为 |
| --- | --- | --- | --- |
| 项目级未筛选 | 告警、操作日志、工单、视频 | “当前项目（未按关联对象筛选）” | 允许进入，不宣称已按对象过滤 |
| 物理站房绑定必需 | 冷冻站工艺总览、设备总览、AI优化总览、空压站首页、锅炉房首页 | “当前物理站房” | 必须存在已发布运行绑定；每个响应都要证明站房筛选，否则不展示业务数据 |
| 冷冻站类型固定作用域 | 趋势、能效、抄表、性能报告、环境、运行诊断 | “冷冻站类型” | 只允许类型级导航；带 `stationId` 时阻止挂载，不能把类型汇总冒充物理站房数据 |
| 设备选择作用域 | 能耗分析、历史数据 | “已选设备（关联对象未自动筛选）” | 当前仅允许冷冻站关联；不宣称数据是按整个站房过滤 |
| 对象专用类型页 | 冷冻站类型页、电力、空调末端首页；未选实例的空压站/锅炉房首页 | 冷冻站/空压站/锅炉房显示对应类型；电力显示“当前项目电力汇总”；空调末端显示“当前楼层末端范围” | 路径固定作用域；对象名称与数据范围必须分开，不得冒充物理实例 |
| 项目配置 | 配置中心、能源参数、知识库 | “当前项目” | 强制移除 `station` |

不允许把前端 `station` 直接当成 BFF 已筛选的证据。后续真正过滤时应使用 `subsystemType`/`stationId`，且只有 BFF 响应明确返回 `dataScope.applied=true` 才能显示“已按站房筛选”。
配置中心状态只证明项目能力与接入配置，不证明现场遥测实时。电力页不得用“配置中心链路：实时数据”表达运行状态；现场状态仍以网关载荷、新鲜度与回路归属门禁为准。
空调末端的控制策略、投运、消缺、签字和最终控制报告属于项目运行证据。前端必须先取得当前 `siteId`、`hvac_terminal`、`fan_coil` 匹配且包含有效设备的末端快照，再加载这些证据；最终控制接口还必须逐报告核对 `siteId`，不匹配或未声明范围的报告按 `scope_mismatch` / `scope_unverified` 隔离，不能把其他项目报告挂到当前页面。
FCU 最终控制证据的文件存储也必须按 `siteId` 隔离。历史站点 `126lnoffice` 为兼容既有交付物继续使用原平面目录；其他站点统一写入 `<outputDir>/sites/<siteId>/fcu-final-control/`。状态读取、刷新、控制门禁、Canary/现场包和管理端签核必须共用同一目录解析规则，禁止不同站点争用同一组 `*-latest` 文件。
任何不兼容的站房与页面组合都不渲染 `<Outlet />`，先显示作用域阻断说明，避免业务组件发出错误范围的请求。

### 2.4 BFF 数据范围证据

运行接口使用统一的 `dataScope` 根字段表达接口实际执行的数据约束：

| 字段 | 含义 |
| --- | --- |
| `siteId` | 本次响应实际使用的项目 |
| `requestedSubsystemType` | 接口显式接收的请求范围；没有请求时必须为 `null` |
| `effectiveSubsystemType` | 接口最终生效的子系统范围 |
| `stationId` | 实际生效的物理站实例；当前未实现实例过滤时必须为 `null` |
| `filterMode` | `fixed_subsystem`、`site_aggregate`、`project_unfiltered`、`device_selected` 或 `station_binding` |
| `applied` | 后端是否真实执行了该范围约束 |
| `reason` | 稳定原因码，不使用展示文案代替合同 |
| `bindingVersion` | 实际执行筛选的已发布运行绑定版本；非站房绑定响应为 `null` 或省略 |

Dashboard trends 是冷站专用聚合接口，根 `dataScope` 固定返回 `effectiveSubsystemType=chilled_plant`、`filterMode=fixed_subsystem`、`applied=true`。Dashboard overview 同时包含冷站指标与项目级告警、室外环境和设备总数，根 `dataScope` 必须返回 `filterMode=project_unfiltered`、`applied=false`、`reason=MIXED_SCOPE_PAYLOAD`，并通过 `fieldScopes.chilledPlantMetrics` 与 `fieldScopes.projectAggregate` 分别给出逐字段证据。`deviceSummary.totalDevices`、`activeAnomalyCount`、室外温湿度、湿球温度和露点属于项目上下文；只有明确列出的冷站指标及四类冷站设备计数属于冷站固定范围。综合总览只有在 `siteId`、`filterMode`、`effectiveSubsystemType`、`applied` 以及首屏 KPI 字段覆盖均匹配时，才显示“冷站指标 · 固定范围”；否则显示“冷站指标 · 范围待核”。

`generatedAt` 只表示 BFF 生成或聚合响应的时间，不是 PLC、网关或测点源时间。综合总览的“源时间”只能来自 overview/trends 的 `freshness.latestTimestamp`；该字段缺失或无效时必须显示“源时间：待证”。页面请求完成时间可另行显示为“刷新时间”，但不得回填“源时间”。

趋势图必须消费自身 `trends.dataScope`，不得借用 overview 的字段级证据。类型级 Dashboard 设备链路仍只能标为“冷站设备类 · 站实例待核”；物理站房设备页则必须由设备目录、设备树、批量详情和单设备详情各自返回 `filterMode=station_binding`、匹配的 `stationId` 与 `bindingVersion`，不得借用其他响应的 `dataScope.applied=true`。

综合总览必须同时区分“能源类型矩阵”和“物理站房登记矩阵”。物理站房矩阵只列出当前项目已发布的站房身份，并如实展示启停状态、运行绑定状态与发布版本；未绑定、绑定草稿、已停用实例也必须保留，便于识别接入缺口。联调/接入阶段按“待绑定或待发布 → 已停用 → 已发布绑定”排序，并在矩阵标题汇总已绑定、待处理和停用数量；不能让需要处理的站房被正常登记项淹没。该矩阵不得把 `bindingState=published` 解释为实时运行，只能提示“运行证据需进入站房页验证”，点击后保留 `siteId`、`station` 与 `stationId`。总览中的冷站设备主链路仍是类型级/客户端设备类型归类，不得因为项目已登记某个冷站，就把类型级数据标题改成该物理站房名称。

能源对象“已发布数量”来自 `/capabilities` 已发布清单，必须与实时、演示、待接和待核等运行证据状态分开统计。`unknown/CHECK` 表示状态待核，不属于已确认链路异常；总览摘要必须写“待核”，只有 `stale/error` 等有明确异常证据的状态才进入“异常”数量。

综合总览“告警 / 诊断事件”的最高风险必须同时消费告警汇总和诊断队列的严重度。若 Top3 中存在 `critical/major/high` 诊断，项目摘要必须显示“最高 高”；不得因为告警计数为 0 或诊断未进入告警汇总而降级成“最高 中/低”。告警条数、诊断项数和最高综合风险仍需分列，不能把诊断项伪装成告警条数。

空压站和锅炉房物理实例复用 `/runtime/summary?stationId=...`。BFF 只能从已发布绑定的设备/点位精确白名单读取数据，并通过配置中心的点位角色映射生成 `stationProcess`；不得按点位名称猜测未配置语义。前端必须再次核验 `dataScope` 的站房、类型和绑定版本。`stationProcess.timestampStatus` 非 `authoritative` 时可以显示隔离后的读数，但只能标为“时间戳待证”，不得标为 LIVE。锅炉效率、单位燃耗等未建立测点或计算合同的指标必须显示 `--`，不得使用演示常数替代。

`/capabilities` 与 `/subsystems` 返回项目内已发布能源对象清单，`dataScope.filterMode=site_aggregate`、`applied=true`，只证明清单按当前 `siteId` 聚合，不证明任何物理站实例已被筛选。响应保持 `items` 一种能源类型一条，并在顶层返回 `stationInstances[]` 与 `stationTotal`；不得把同类型多个实例平铺进 `items`，否则现有按 `subsystemType` 建立的矩阵会静默覆盖。两条路径、响应类型和示例必须纳入 OpenAPI 与路由测试。

### 2.5 物理站房身份合同

物理站房登记是身份与导航合同，不是运行数据过滤合同：

| 字段 | 规则 |
| --- | --- |
| `stationId` | 项目内稳定唯一；不得根据可修改的站房名称动态生成 |
| `stationName` | 工程人员确认的展示名称 |
| `parentSubsystemType` | 必须引用同一响应 `items[].subsystemType`，且物理站房实例的父类型属于“供能站房”语义组 |
| `status` | 站房身份登记状态；不得从父类型状态自动推断 |
| `sourceStatus/freshnessStatus/alarmCount` | 只允许由真实运行响应或独立证据账本派生；身份表单不得写入，无告警筛选证据时 `alarmCount=null` |
| `published` | 新登记默认未发布；经配置版本发布后才进入运行壳层 |

配置中心提供 `GET/PUT /admin/v1/sites/{siteId}/stations`。PUT 仅登记或更新实例，不删除未提交实例，也不创建 PLC、设备、点位或控制绑定；站点管理员可写、审计员只读。配置快照版本 2 包含站房实例，旧快照不含 `stationInstances` 时，回滚不得删除当前站房登记。

当前项目尚无物理站房实例时，左侧导航与综合总览必须保留“当前按能源类型导航”的真实空状态，并提供“查看站房登记”入口。入口只进入当前 `siteId` 的项目配置中心，必须移除 `station` 与 `stationId`；不得自动创建默认站房、设备/点位绑定或 PLC 控制关系。能力清单仍在加载或请求失败时不显示该入口，避免把“证据待核”误判成“实例为零”。

URL 使用 `station=<subsystemType>&stationId=<physicalStationId>`。`station` 保持原有类型兼容语义，`stationId` 只表示已校验的物理实例关联。未知实例、类型不匹配、能力清单未完成校验、绑定未发布或当前页面不支持站房筛选时，壳层不挂载业务页。

### 2.6 物理站房运行绑定合同

站房身份与运行数据边界必须分层：

`身份登记 → 绑定草稿 → 真实只读验证 → 他人审批发布 → 运行接口实际筛选 → 响应证据`

- `GET /admin/v1/sites/{siteId}/stations/{stationId}/runtime-binding` 同时返回 `draftBinding`、`publishedBinding`、`draftVersion` 与 `publishedVersion`。
- `PUT .../runtime-binding` 只保存新草稿，必须携带 `expectedVersion`；保存草稿不得改变当前发布 head。
- `POST .../runtime-binding/validate` 使用真实设备/点位目录做只读验证。0 行、placeholder、fallback、通配、设备 ID/编码错配、未匹配点位或跨设备歧义均失败。
- `POST .../runtime-binding/publish` 仅 `platform_admin` 可用；发布人与本草稿创建者/编辑者必须分离，验证哈希与载荷哈希必须一致，站房身份必须已启用并发布，设备白名单不得与其他已发布站房重叠。
- 顶层 `bindingState/bindingVersion` 表示运行端当前已发布 head；新草稿通过 `draftBindingVersion` 单独表达，不得让草稿遮蔽仍有效的发布版本。
- 运行端只在设备列表、设备树、批量详情、单设备详情和运行摘要五类只读接口接受 `stationId`。其他接口返回明确阻断，不得静默回退到项目全量数据。
- 成功响应必须同时证明 `siteId`、`requestedSubsystemType`、`effectiveSubsystemType`、`stationId`、`filterMode=station_binding`、`reason=STATION_RUNTIME_BINDING_APPLIED`、`applied=true` 与 `bindingVersion`。
- 已发布只表示运行端可申请使用该绑定，不等于实时、数据新鲜或无告警。UI 只有消费并校验本次响应证据后才能显示“站房筛选已验证”。

### 2.7 配置中心可达性与登记空状态

3001 是固定运行入口，3002 是独立管理端口；出现 3002 路由并不等于管理服务当前可达。3001 的项目配置页必须在渲染外链前执行有界可达性核验：

- 核验时间必须有明确上限，不能让配置页长期停在加载态。
- 3002 可达时，入口携带当前 `siteId`，并强制移除 `station` 与 `stationId`。
- 3002 不可达时，不保留已知死链接；必须显示“配置中心未启动”和可重复核验的重试操作。
- 可达性只证明 Web 入口存在，不证明登录有效、管理 API 健康或写入门禁开放。

物理站房登记页的空状态必须同时解释“实例数量”和“可登记类型”，不能用“类型 0”代替“实例 0”：

- 只读模式仍显示主操作，但以禁用状态标记“登记站房（只读）”，并说明写入保护。
- 页面交叉展示全局物理供能类型注册表与当前项目的能力状态，例如“可登记供能类型 3”“已启用 1 · 待配置 2”。
- 空状态列出冷冻站、空压站、锅炉房等可登记父类型及其当前项目状态；不得因实例为 0 推断类型不存在。
- 登录页密码默认必须为空；演示、mock 或开发凭据不得作为预填值交付到 UI。
- 860px 以下登录任务必须先于品牌说明出现，用户名、密码和进入按钮应在首屏可达；品牌介绍可以保留在登录任务之后。
- 物理站房为 0 时，移动端数字摘要优先使用 2×2，避免四张单列卡片把关键空状态推迟约两屏；360px 以下允许回退单列。
- 空状态不得自动创建默认站、PLC、设备/点位或运行绑定。

## 3. 状态真值规则

| 状态 | 菜单表达 | KPI 规则 | 颜色 |
| --- | --- | --- | --- |
| `live` | 已接入 | 可参与实时 KPI | 绿色 |
| `demo` | 演示数据 | 不参与真实 KPI | 蓝色 |
| `waiting` | 待接实时 | 不显示假 KPI | 黄色 |
| `stale` | 数据陈旧 | 不参与实时 KPI | 黄色 |
| `error` | 链路异常 | 不参与实时 KPI | 红色 |
| `not_configured` | 未配置 | 不参与统计 | 黄色/灰色 |
| `not_applicable` | 不适用 | 不显示站点入口 | 不显示 |
| 能力接口失败 | 状态待核 | 不推断健康 | 中性 |

能力接口请求失败或加载中时不得清空整个站点导航；入口保留并明确标记“状态待核”。

能力登记与运行证据必须交叉核验。若能力中心仍标为“演示/待接/未配置”，但同一 `siteId` 的冷站实时接口已经通过字段范围和源状态校验，UI 不得擅自覆盖成 `LIVE`，也不得继续静默显示 `DEMO`；应标为 `CHECK` 和“配置与运行证据冲突”，不计综合 KPI，交由工程人员校准配置。

## 4. 权限规则

| 工作视角 | 已配置站点 | 未配置站点 | 控制边界 |
| --- | --- | --- | --- |
| 运行观察 | 可见 | 隐藏 | 只读 |
| 运行值守 | 可见 | 隐藏 | 沿用运行权限与 PLC 保护 |
| 工程运维 | 可见 | 可见 | 仅提供接入/配置入口，不绕过审批和 PLC |

导航可见性不是后端授权。任何写操作仍必须由 BFF 权限、审批流程和 PLC 安全边界共同校验。

## 5. 路由与扩展

- 站内页面由 URL 路径确定能源类型；值班、分析、AI、诊断等公共模块由 `station=<subsystemType>` 恢复关联类型；物理站房由 `stationId` 恢复，项目由 `siteId` 查询参数确定。
- 中央路由策略若明确只支持一种能源类型，壳层必须将该类型显式化为页面固定关联：左侧选中对应能源对象，顶部显示“能源对象工作区”，并在工作区子链接中携带 `station`。例如能效、趋势、AI 和冷站诊断页不得同时显示“项目工作区 / 全部能源对象 / 冷冻站数据范围”。
- 路径站房优先于 `station` 参数。非法、当前角色不可见或不适用的站房参数不构成当前站房上下文。
- 能源对象工作区互跳和兼容的项目级模块必须保留 `station`、已校验的 `stationId` 与 `siteId`；项目工作区不伪造具体对象关联；不兼容的冷站专属页不得挂载；综合总览和项目配置必须移除两项站房上下文。
- 项目切换必须清除旧项目 `stationId`；类型上下文只有在新项目能力清单中仍可见时才继续使用。
- 新增能源站或配用能子系统类型时，只向 `ENERGY_STATION_DEFINITIONS` 注册业务对象及其站内功能，不复制公共模块。
- 同一供能站房类型存在多个物理实例时，左侧最多展开到“供能站房类型 → 物理站房实例”两级；使用原生 disclosure 按钮和链接，不伪装成未实现完整方向键模型的 ARIA tree。配用能系统保持独立语义，不套用“物理站房实例”层级。

`station` 当前只表示可刷新、可回退的“导航关联上下文”。在页面与 BFF 尚未按子系统完成真实过滤前，UI 只能写“关联对象”，项目级页面必须写“未按关联对象筛选”，不得宣称“已筛选为该站房”。真实过滤属于后续数据合同任务。

## 7. 验收标准

- 左侧按“供能站房”和“配用能系统”分组：冷冻站、空压站、锅炉房进入前者，电力监控、空调末端进入后者。
- 能力响应可同时返回两个 `chilled_plant` 物理实例而不重复或覆盖类型能力；左侧按“冷冻站 → 冷冻站 A/B”两级呈现。
- 没有已发布实例时明确显示“物理站房实例未登记”，不自动伪造“默认站”。
- 电力监控、空调末端不得被标注或统计为物理站房；物理站房实例不得与能源类型同级展示。
- 桌面左侧不存在值班、分析、AI优化、诊断和配置大卡片，只保留综合总览，以及分为“供能站房/配用能系统”的业务对象列表。
- 横向二级导航不再重复呈现多个站点；选择冷冻站时只显示工艺总览、系统孪生等站内功能。
- 桌面内容区顶部右侧可进入总览/运行、值班、分析、AI优化和诊断；项目页必须明示“项目工作区”，关联冷冻站、空压站等对象后必须改为“能源对象工作区”；配置通过独立全局入口进入。
- 桌面端展开工作区后可一次看到兼容的二级功能；冷冻站为值班 3、分析 6、AI优化 2、诊断 4、项目配置 3，其他对象的未接入模块显式禁用，不伪造数量。
- 左侧站房卡片显示站房能力摘要，不再显示容易误解的“1项”。
- 选中物理站房后进入公共模块，URL 同时保留 `station`、`stationId` 与 `siteId`，左侧精确实例保持选中；无对象上下文时明确显示“项目工作区 / 全部能源对象”。
- 配置入口不携带 `station` 或 `stationId`，明确作用于当前项目，不得暗示配置只影响当前站房。
- 3002 未启动或核验超时时，配置卡不得保留 3002 外链；页面明确显示“配置中心未启动”并提供可重试操作。3002 可达只表示入口可访问，不得解释为管理 API 或写入门禁健康。
- 物理站房实例为 0 时，登记页仍显示禁用的“登记站房（只读）”、全局可登记供能类型数量和当前项目“已启用/待配置”状态；不得显示误导性的“供能站房类型 0”。
- 管理端登录密码默认空白；代码和构建产物不得包含表单预填开发密码。
- 390px 管理端登录首屏应完整出现空密码输入和“进入后台”按钮；站房登记页无横向溢出，四张摘要按 2×2 展示，只读主操作保持不少于 44px 且文字可辨识。
- 切换项目时不得把原项目 `stationId` 带入新项目；未知或父类型不匹配的实例必须显示作用域阻断面板，不挂载业务页。
- 仅有关联实例但 BFF 未返回实例过滤证据时，数据范围必须显示“未按物理实例筛选”，不得显示“已按冷冻站 A 筛选”。
- 顶部同时显示“关联对象”与“数据范围”；告警、日志、工单和视频页显示“当前项目（未按关联对象筛选）”。
- `/energy-efficiency?station=compressed_air` 等不兼容组合必须显示作用域阻断面板，不渲染冷站页面，不发冷站业务请求。
- `/compressed-air?...&stationId=...` 与 `/boiler-room?...&stationId=...` 必须校验本次 `/runtime/summary` 的 `station_binding` 证据；绑定缺失、站房停用或响应范围不匹配时不挂载项目级数据。
- 非历史项目刷新 FCU 最终控制状态后，所有 `*-latest` 文件必须落在该项目独立目录；连续刷新两个项目不得改写第一个项目的证据，控制门禁也不得读取其他项目目录。
- 空压站功率、压力、流量和单耗只使用已映射站房点位；锅炉房只展示已建立合同的功率、压力、热媒流量和温度，未配置指标不使用演示常数补齐。
- 综合总览逐站列出冷冻站、空压站和锅炉房物理实例，包括未绑定与已停用实例；绑定发布状态只作为入口与配置证据，不标记 LIVE，点击后由站房页重新验真。
- 综合总览的待绑定/待发布站房必须排在已停用和已发布绑定站房之前，标题同时汇总“已绑定 / 待处理 / 停用”；桌面宽屏使用单行可读卡片，移动端保持一站一卡。
- 能源对象已发布数量不得因运行状态为 `CHECK` 而变成 0；`CHECK` 进入“待核”数量，不得冒充“异常”。
- Top3 出现高严重度诊断时，项目级“最高风险”必须同步为“高”，即使当前告警条数为 0；告警与诊断数量仍分别统计。
- BFF `generatedAt` 不得显示为现场“源时间”；无有效 `freshness.latestTimestamp` 时显示“源时间：待证”，刷新时间独立表达。
- 综合总览的冷站设备主链路必须标记为“冷站类型级”，不得从 `stationInstances[]` 取第一个站名冒充物理站房数据范围。
- 移动端总览按“能源类型 → 物理站房实例”单栏排列，一站一卡；桌面三栏规则不得覆盖移动断点。站房页的绑定版本、数据范围和“时间戳待证”等关键证据必须换行完整展示，不得使用省略号隐藏。
- 站内功能二级导航与站房工作区职责不同，不使用同一强高亮层级制造重复选中感。
- 冷冻站具体实例的顶部站内导航只显示实例安全的工艺总览；右侧运行/分析/AI/诊断分别为 1/未接入/1/2，不得把会触发实例作用域阻断的类型级页面计入可用数量。清除 `stationId` 后类型级 4/6/2/4 能力恢复。
- 未配置站点仅工程运维视角可见；不适用站点所有视角均不显示。
- 实时、演示、待接、陈旧、异常、未配置和待核状态有明确文案，异常使用红色。
- 能力登记与运行接口证据冲突时显示 `CHECK`，不得自动升级为 `LIVE`，也不得把已回传实时证据继续静默归类为演示数据。
- 能力接口失败不会导致全部站点入口消失，也不会渲染为绿色健康。
- 有活动告警的站点显示告警数量，数量来自能力接口，不在前端伪造。
- 900px 以下使用抽屉导航，触控目标不小于 44px，关闭后不可聚焦抽屉内部元素。
- 移动抽屉以手风琴呈现五类上下文工作区和项目配置，并同样区分“项目工作区”与“能源对象工作区”；展开后子功能数量与桌面端一致。

- 桌面和移动端均不存在“左侧站点 + 顶部同一批站点”的重复导航。
- `npm run check:multi-energy-navigation`、`npm run build` 通过。
- Dashboard 首屏先呈现当前项目能源对象状态矩阵；冷站 KPI 与趋势分别核验自身范围证据，设备主链路标明“冷站设备类 · 站实例待核”，BFF 未确认时不得显示“冷冻站固定范围”。
- Dashboard overview/trends 的 OpenAPI 示例与运行响应都包含 `dataScope`；overview 另含字段级 `fieldScopes`，且 `station` 导航参数不会被伪装成 `applied=true`。
