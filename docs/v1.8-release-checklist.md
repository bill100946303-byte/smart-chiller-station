# V1.8 发布前检查清单

## 一键执行
```bash
/Users/billchow/Documents/智慧冷冻站/scripts/release_preflight_v1_8.sh
```

在受限环境（端口/网络受控）可使用“运行态可选”模式：
```bash
RUNTIME_REQUIRED=0 /Users/billchow/Documents/智慧冷冻站/scripts/release_preflight_v1_8.sh
```
说明：该模式会自动传入 `READINESS_CHECK=0`，不会刷新 `readiness/badge` 运行态产物。

## 检查范围
1. 栈健康与非降级门槛（`check_stack.sh`）
2. BFF 合同门禁（`npm run check:contract`）
3. Shell 构建门禁（`npm run build`）
4. 关键产物存在性（`ui-badge-state-v1.8.json` 等）

## 通过标准
- `check_stack.sh` 输出：
  - `Readiness: PASS`
  - `ND failed: 0`
- `check:contract` 输出：`Contract validation passed for 5 examples`
- `shell build` 输出：`built in ...`
- 关键文件均存在：
  - `docs/ui-badge-state-v1.8.json`
  - `apps/chiller-shell-v1/public/ui-badge-state-v1.8.json`
  - `docs/v1.8-signoff-decision.md`
  - `docs/ui-consistency-review-v1.8.md`
  - `docs/readiness-baseline-freeze-v1.8.md`

## 输出产物
- 日志：`docs/v1.8-release-preflight.log`
- 报告：`docs/v1.8-release-preflight.json`
  - 包含：`gates.stackOk/contractOk/shellOk/runtimeRequired/readinessGateEnabled`、`runtimeArtifactsSkipped` 与 `preflightPass`

## 备注
- 该流程不修改业务规则阈值，仅做发布前门禁与基线验证。
- 若 `runtime-ready` 在合同探针中为 `unknown`，以 `check_stack.sh` 的 readiness 结果为主。
- 若前端由 `dist` 目录直出（如本地 nginx），角标文件需同步到 `dist/ui-badge-state-v1.8.json`；当前脚本已内置该同步。
