## 说明
- 脚本会自动确保 `3001` 指向 shell 入口，并同步角标文件到 `docs/public/dist` 三处路径。
- 不会修改规则阈值或业务字段定义，只做验收与状态同步。
- 为避免受限环境误覆盖，若检测到所有健康与业务端点均为 `000`，默认只写入 `*.unavailable.*` 快照，保留最近一次 canonical 报告。
- 如需在该场景下强制覆盖 canonical，可显式设置：`WRITE_CANONICAL_ON_UNAVAILABLE=1`。
- 预演模式使用：`chiller_ctl.sh accept --dry-run`。该模式不写 `docs/` 下 canonical 报告，只写 `/tmp` 预演产物。
- 放行命令：`chiller_ctl.sh release-gate`。该命令不改数据，只读取门禁结果并返回退出码（GO=0，NO-GO=1）。
- JSON 输出：`release-gate --json`，字段包含 `decision/exitCode/freshness/strictFreshness` 等，可直接机读。
- reasons 输出：文本与 JSON 都包含 `reasons`，用于标记 NO-GO 的具体原因（未命中时为空数组或 `none`）。
- advisories 输出：文本与 JSON 都包含 `advisories`，用于标记 GO 态下的非阻断提示（未命中时为空数组或 `none`）。
- `release-gate-latest` 会把当前放行结果固化到 `docs/release-gate-latest.{json,md}`，便于预检脚本和发布记录复用。
- `preflight --strict-freshness` 会以严格时效模式执行 release gate 同步（`strictFreshness=true`），并写入预检报告 `gates.releaseGateStrictFreshness`。
- 时效阈值：默认 `warn=30min`、`stale=60min`（可通过环境变量 `FRESH_WARN_MIN/FRESH_STALE_MIN` 覆盖）。
- 严格模式：`--strict-freshness` 下，只有 `freshness=fresh` 才会 GO。
