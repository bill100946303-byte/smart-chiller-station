# 冷站系统 2.0 数据建模 / 拓扑线程 V1

## 1. 本次结论

基于当前可用库和旧系统结构，冷站 2.0 第一版数据模型建议分成 4 层：

1. 项目层
   - 来源：`zsqy_v1.appmanager`
   - 作用：站点、模型地址、项目模板、项目级绑定变量
2. 设备资产层
   - 来源：`126lnoffice.drtypeinfo`、`126lnoffice.drinfo`
   - 作用：设备类型树、设备实例、设备坐标、资产属性
3. 实时点位层
   - 来源：`126lnoffice.reg`、`126lnoffice.qstag`、`126lnoffice.sub`、`126lnoffice.subinfo`
   - 作用：实时值、状态值、报警值、单位、显示规则、枚举翻译
4. 聚合统计层
   - 来源：`zsqy_v1.param_type`、`zsqy_v1.energy_statistics_minute/hour/day/month`
   - 作用：首页指标口径编码、小时/日/月统计、趋势与诊断

当前项目关键事实：

- 项目主键：`appid=126`
- 项目名：`lnoffice`
- 设备库：`126lnoffice`
- 统计库：`zsqy_v1`
- 原始历史采样：`126lnoffice_data.tagdata_YYYYMMDD`
- 当前设备主类型：
  - `CHP` 冷冻水泵
  - `CH` 主机/冷机
  - `CTF` 冷却塔风机
  - `CWP` 冷却水泵
  - `SY` 系统控制
- 当前没有单独的“冷却塔塔体设备实例”，只有：
  - `CTF` 冷却塔风机实时点
  - `CTE` 冷却塔电量虚拟设备
  - `CTHDE` 冷站总散热量虚拟设备

## 2. 第一阶段必须先统一的指标口径

这部分必须先锁定，否则首页、总览、诊断、AI 建议会出现同名不同义。

### 2.1 命名统一

1. 功率统一用 `kw`
2. 电能/累计能耗统一用 `kwh`
3. 瞬时冷量/瞬时散热量统一用 `kw`
4. 累计制冷量/累计散热量统一用 `kwh`
5. 温差统一定义为：
   - 冷冻水温差 = 回水温度 - 供水温度
   - 冷却水温差 = 供水温度 - 回水温度
6. 累计量字段禁止再叫“实时总电量”
   - 现有 `totalElectricity` 实际是累计电能，不是实时功率
   - V2 统一命名为 `station_total_energy_kwh`

### 2.2 公式统一

1. `station_total_power_kw`
   - 定义：冷机功率 + 冷冻泵功率 + 冷却泵功率 + 冷却塔功率
   - 当前对应：`totalPower = @409@ + @425@ + @455@ + @440@`
2. `station_total_energy_kwh`
   - 定义：冷机累计电能 + 冷冻泵累计电能 + 冷却泵累计电能 + 冷却塔累计电能
   - 当前对应：`totalElectricity = @411@ + @427@ + @442@ + @457@`
3. `station_cooling_capacity_kw`
   - 推荐定义：`冷冻水流量(m3/h) * 冷冻水温差(C) * 1.163`
   - 当前字段存在但未正常更新：`totalCoolingCapacity`
4. `station_heat_rejection_kw`
   - 推荐定义：`冷却水流量(m3/h) * 冷却水温差(C) * 1.163`
   - 当前字段存在但未正常更新：`instantaneousHeatDissipation`
5. `station_cop`
   - 定义：`station_cooling_capacity_kw / station_total_power_kw`
   - 分母小于等于 0 时返回 `null`，不能返回 `0` 或 `Infinity`
6. `thermal_unbalance_rate_pct`
   - 定义：`((station_cooling_capacity_kw + chiller_power_kw - station_heat_rejection_kw) / station_heat_rejection_kw) * 100`
   - 分母小于等于 0 时返回 `null`

### 2.3 数据源统一

1. 首页实时卡片优先读实时层
   - `126lnoffice.qstag`
   - 或 `qstag` 内公式点
2. 首页趋势和同比环比优先读统计层
   - `zsqy_v1.energy_statistics_hour/day/month`
3. 异常诊断原始序列优先读原始历史表
   - `126lnoffice_data.tagdata_YYYYMMDD`
4. 不再同时把同一指标当成“实时点”和“统计结果”双主源

### 3.2 首页字段使用建议

1. 首页顶部主卡片建议固定 6 项
   - `station_total_power_kw`
   - `station_total_energy_kwh`
   - `station_cooling_capacity_kw`
   - `station_cop`
   - `running_device_count`
   - `alarm_device_count`
2. 首页中部冷热侧运行卡片建议固定 6 项
   - `chilled_supply_temp_c`
   - `chilled_return_temp_c`
   - `chilled_delta_t_c`
   - `cooling_supply_temp_c`
   - `cooling_return_temp_c`
   - `cooling_delta_t_c`
3. 首页环境卡片建议固定 4 项
   - `wet_bulb_temp_c`
   - `outdoor_temp_c`
   - `outdoor_humidity_pct`
   - `dew_point_temp_c`

### 4.5 冷却塔模型

这里必须区分“塔体对象”和“当前已有采集对象”。

当前已有对象不是完整的塔体，而是：

1. 实体设备：`CTF1` 冷却塔风机
2. 虚拟能耗设备：`CTE1` / `CTE`
3. 虚拟散热量设备：`CTHDE`

所以 V1 建议把冷却塔建成**组合设备**：

```json
{
  "composite_device_id": "CT-1",
  "device_type_code": "CT",
  "device_type_name": "冷却塔",
  "member_devices": [
    {"device_id": 3, "role": "fan"},
    {"device_id": 49, "role": "energy_meter_virtual"},
    {"device_id": 53, "role": "heat_rejection_virtual"}
  ],
  "metrics": {
    "fan_power_kw": 0.0,
    "fan_energy_kwh": 4380.1,
    "fan_output_freq_hz": 0.0,
    "heat_rejection_kwh": 0.0
  }
}
```

冷却塔 V1 结论：

- 前端展示可以继续叫“冷却塔”
- 但接口实现上不能假设有单独 `CT` 实体设备
- 必须允许组合设备或虚拟设备聚合

## 5. 拓扑模型

## 5.1 当前拓扑事实

当前库里没有显式的“边关系表”，只有：

1. 类型树关系
   - `drtypeinfo.parentid`
2. 设备实例
   - `drinfo`
3. 设备点位与实时值
   - `reg + qstag`
4. 项目 2D 页面绑定点
   - `appmanager.model2d_dataId`

这意味着当前可以做“树状结构”，但不能稳定做“工艺流向图”。

## 5.3 冷站 V1 推荐逻辑拓扑

建议前端先按下面的 4 条主链路展示：

1. 冷冻水回路
   - `T102(冷冻回水主管温度)` -> `CHP1(冷冻泵)` -> `CH1(冷机蒸发侧)` -> `T101(冷冻供水主管温度)`
2. 冷却水回路
   - `T202(冷却回水主管温度)` -> `CWP1(冷却泵)` -> `CH1(冷机冷凝侧)` -> `CT-1(冷却塔组合设备)` -> `T201(冷却供水主管温度)`
3. 电力回路
   - `CH1`、`CHP1`、`CWP1`、`CTF1` -> `station_total_power_kw` / `station_total_energy_kwh`
4. 控制回路
   - `SY(系统控制)` -> `CH1`、`CHP1`、`CWP1`、`CTF1`

## 7. 当前缺口

## 7.1 指标层缺口

1. `station_cooling_capacity_kw`
   - 当前字段存在，但 `qstag.totalCoolingCapacity` 长期停留在旧时间，现值为 `0`
2. `station_heat_rejection_kw`
   - 当前字段存在，但 `qstag.instantaneousHeatDissipation` 长期停留在旧时间，现值为 `0`
3. `thermal_unbalance_rate_pct`
   - 当前已经会算出 `Infinity`
   - 说明分母保护和空值规则没有统一
4. `station_total_energy_kwh`
   - 当前被命名成“实时总电量”
   - 口径实际是累计电能

## 7.2 采集层缺口

1. `T101/T102/T201/T202` 当前实时值为 `0.0`
2. `FT201` 当前实时值为 `0.0`
3. `WM1` 当前实时值为 `0.0`
4. 没有稳定可用的实时流量和温差，导致冷量/散热量/能效链路都不可信

## 7.3 结构层缺口

1. 没有显式拓扑边关系表
2. 没有 `site -> system -> loop -> device` 的统一主键体系
3. 冷却塔没有独立塔体实例，只能拼装组合设备
4. 首页配置同时存在：
   - `126lnoffice.homepage_param`
   - `zsqy_v1.param_type`
   - 两套字典必须收敛成一套

## 7.4 页面层缺口

1. 首页字段可以做，但部分能效卡片当前只能展示 `null/待接入`
2. 系统总览能做树和卡片，工艺流向需要补配置
3. 异常诊断页有原始历史表基础，但还没有统一异常事件模型
4. AI 建议页要先依赖异常诊断的结构化输出，不能直接吃散点位
