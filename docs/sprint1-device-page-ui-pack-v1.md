# Sprint1 设备总览页 UI Pack v1

## 结论

- 设备总览页首版是否可直接进入开发：`yes`
- 结论前提：首版只做“值班可读”的设备总览，不扩到设备详情抽屉、控制操作、复杂筛选和批量命令。

## 页面定位

设备总览页不是资产台账页，也不是设备控制台。  
首版目标只有 3 个：

1. 让值班同学先判断当前冷站各系统分组是否健康。
2. 让值班同学快速定位“哪一类设备 / 哪一组设备”存在问题。
3. 在不打开详情抽屉的前提下，先拿到一层足够稳定的设备树或设备列表骨架。

已确认的迁移依据：

- 旧系统已有设备数据接口：`GET /api/device/126lnoffice/data`
- 旧系统已有设备树接口：`GET /api/device/126lnoffice/data/tree`
- 新壳已有静态系统总览骨架：`SystemOverviewPage`

## 页面信息架构

阅读顺序固定为：

1. 页头与来源状态
2. 顶部摘要卡
3. 系统/设备分组概览
4. 设备状态总览区
5. 简化设备树或设备列表骨架

不要把设备树放到第一屏最顶。  
设备总览页的第一反应应该是“哪组异常”，而不是“先钻树结构”。

## 模块拆分

### 1. 页头区

- 模块名：`DeviceOverviewHeader`
- 组成：
  - 页面标题、副标题
  - `ReadinessBadge`
  - `SourceStatusBanner`
  - 一行页面说明
- 作用：
  - 先确认来源状态，再进入设备阅读。

### 2. 顶部摘要卡

- 模块名：`DeviceSummaryStrip`
- 组件：4 到 6 个 `StatCard`
- 首版建议卡：
  - 在线设备数
  - 告警设备数
  - 通讯异常数
  - 自动运行设备数
  - 待人工确认设备数
  - 数据新鲜度
- 作用：
  - 用一层聚合指标回答“当前设备面整体是否稳”。

### 3. 系统/设备分组概览

- 模块名：`DeviceGroupOverview`
- 组件：
  - `SectionCard`
  - `StatusPill`
  - 分组概览卡片
- 建议分组：
  - 冷机组
  - 冷冻泵组
  - 冷却泵组
  - 冷却塔组
  - 末端负荷 / 辅机
- 每组展示：
  - 在线/总数
  - 当前主状态
  - 是否有告警
  - 一句风险或提示
- 作用：
  - 这一层是“先找异常系统，再看设备树”的主入口。

### 4. 设备状态总览区

- 模块名：`DeviceStateBoard`
- 组件：
  - `SectionCard`
  - 状态分布条
  - 小型状态卡
- 建议内容：
  - 运行中
  - 待机
  - 告警
  - 离线/通讯异常
  - 维护中
- 作用：
  - 用状态分布代替一开始就看长列表。
  - 帮值班同学先判断是“局部异常”还是“整体掉线”。

### 5. 简化设备树 / 列表骨架

- 模块名：`DeviceTreeOrListPanel`
- 组件：
  - `SectionCard`
  - 左：树骨架 `DeviceTreeSkeleton`
  - 右：设备列表骨架 `DeviceListSkeleton`
- 首版建议：
  - 桌面端优先用“两列”结构：
    - 左列：系统分组树 / 设备树骨架
    - 右列：选中分组下的设备列表骨架
  - 不做真实右侧详情抽屉
- 列表字段建议：
  - 设备名
  - 设备编码
  - 所属系统
  - 当前状态
  - 当前功率 / 当前频率 / 温度（按设备类型最小差异显示）
  - 最近更新时间
- 作用：
  - 先把浏览结构搭起来，为后续详情页和控制页留接口。

## 桌面端优先布局

### Desktop >= 1180px

- 第一行：页头 + 来源状态
- 第二行：6 卡摘要区
- 第三行：分组概览区（5 张系统组卡）
- 第四行：
  - 左 7 列：设备树 / 列表骨架主区
  - 右 5 列：设备状态总览区 + 风险摘要

建议栅格：

- 摘要区：`repeat(6, minmax(0, 1fr))`
- 分组概览：`repeat(5, minmax(0, 1fr))`
- 主体区：`1.4fr 0.9fr`

### Tablet 900px - 1179px

- 页头纵向堆叠
- 摘要区改为 3x2
- 分组概览改为 2 列
- 设备树 / 状态总览改为上下结构

## 移动端简化策略

### Mobile < 900px

- `SourceStatusBanner` 保留，但 detail 默认折叠
- 摘要卡改为单列或 2 列
- 分组概览卡保留，但每卡只显示：
  - 分组名
  - 在线/总数
  - 主状态 pill
  - 一句风险提示
- 设备状态总览区保留为纵向堆叠卡，不做横向状态带
- 设备树与设备列表不做双栏：
  - 先显示“分组列表”
  - 再显示“该分组设备列表骨架”
- 禁止横向滚动

## 状态落点

### normal

- 来源状态：`good`
- 摘要卡：在线数、自动运行数、freshness 均为正常态
- 分组概览：大部分系统组为 `good / neutral`
- 状态总览区：告警、离线项占比低
- 列表骨架：正常显示简化设备列表

### partial

- 来源状态：`warn`
- 页面表达：
  - 页面仍可读
  - 某些系统组显示“部分字段缺失 / 仍可查看在线态”
- 适合场景：
  - 设备在线状态有，部分运行值缺
  - 树接口有，列表字段不全
- 原则：
  - partial 不能做成整页失败
  - 风险要落在分组卡与列表字段缺口提示里

### degraded

- 来源状态：`warn`
- 页面表达：
  - 顶部来源条先给原因
  - 摘要卡只保留仍可读的聚合值
  - 状态总览区标出“当前仅展示部分来源”
  - 设备树 / 列表区显示降级说明与骨架占位
- 原则：
  - degraded 允许值班先看大盘，但不允许误导成“设备本身全挂”

### stale

- 来源状态：可 `good` 或 `warn`
- 页面表达：
  - 摘要卡 freshness 标为 stale
  - 分组概览仍可显示上次快照
  - 列表区顶部显示“当前为最近一次有效快照”
- 原则：
  - stale 是时间问题，不是结构问题
  - 页面不能白屏

### empty

- 触发条件：
  - 当前设备数据未返回任何分组或设备项
- 页面表达：
  - 摘要卡以 `--` 或 0 占位
  - 分组区给空态说明
  - 树 / 列表区给“当前无可展示设备数据”
- 原则：
  - empty 不自动等于 degraded
  - 只有来源异常时，才配合 degraded 提示

## 首版不做项清单

- 不做设备详情抽屉
- 不做远程控制操作
- 不做批量命令
- 不做复杂筛选器
- 不做配置编辑与台账维护
- 不做 2D/3D 设备联动
- 不做多层 drilldown

## 开发收口建议

- 先把页面定位锁成“设备值班总览页”，不要和系统总览页争角色。
- 首版只要做到：
  - 顶部聚合可读
  - 分组风险可读
  - 设备浏览骨架稳定
  - 五类状态落点明确
- 设备树和设备列表都先走骨架方案，为后面真实接口接入留槽位，不要一开始就把复杂交互做死。

## 最终拍板

- 设备总览页首版是否可直接进入开发：`yes`
- 理由：
  - 旧系统已确认存在设备数据和设备树接口，业务承接路径清楚。
  - 新壳现有组件足以覆盖首版 70% 以上视觉与结构。
  - 本版边界明确，适合 Sprint 1 直接进入页面开发与接口联调。
