# 中文文案与字段口径一致性核对 v1

目标：防止“展示文案”与“数据语义”漂移，供前端与规则侧统一使用。  
参考基线：`docs/field-dictionary.json (v1.0.1)`、`docs/metric-availability-v1.md`、当前壳层前端页面文案。

## 1) 字段映射核对表（展示文案 -> 字段 -> 单位 -> 结论）

| 展示文案（现状） | 对应字段/来源 | 单位（现状） | 口径基线 | 结论 |
| --- | --- | --- | --- | --- |
| `总站功率` | `station_total_power_kw`（`overview.energyCards.totalPowerKw`） | `kW` | 冷站实时总功率（`totalPower` 主口径） | 基本一致；建议文案改为“冷站实时总功率”，避免“总站”歧义。 |
| `当前 COP` | `station_cop`（`overview.energyCards.currentCop`） | 空字符串 | 冷站 COP，`null_strategy=return_null`，禁止 `NaN/Infinity` | 语义一致；建议单位显示为 `-`（或“无量纲”），不要留空。 |
| 趋势中的 `chilledDeltaT`（自动 prettify） | `chilled_delta_t_c`（趋势序列） | 未显示 | 冷冻水温差（℃） | 存在语义风险：未明确中文名与单位。建议固定“冷冻水温差（℃）”。 |
| 趋势中的 `coolingDeltaT`（自动 prettify） | `cooling_delta_t_c`（趋势序列） | 未显示 | 冷却水温差（℃） | 存在语义风险：未明确中文名与单位。建议固定“冷却水温差（℃）”。 |
| `今日累计电量` | `station_total_energy_kwh`（前端字段名 `totalElectricityKwh`） | `kWh` | 字典已标注风险：`totalElectricity` 实为累计电能 | **高风险**：若未做“按日切片”，`今日`会误导。建议改“累计电能（kWh）”，或仅在确认日界切片时显示“今日累计电能”。 |
| `当前异常数` | 实际取 `anomaly.counts.total`（告警流汇总） | `项` | 告警相关字段单位为`条`，来源为告警日志/告警汇总 | **高风险**：文案“异常”与来源“告警”混用；建议改“当前告警事件数（条）”或“最近告警条数”。 |
| `高等级/中等级/低等级`（实时状态） | `alarmSummary.high/medium/low` | 条目计数 | 告警等级计数 | 语义可用；建议在文案明确“告警等级”，避免与“风险等级”混淆。 |
| 建议卡 `风险 高/中/低` | `recommendations.cards[].risk`（high/medium/low） | 无 | 规则 risk 与 severity 分离 | 映射基本一致；建议保留“风险”前缀，并避免把 severity 文案混入 risk。 |

补充检查（单位与换算）：

- 当前未发现 `W`/`kW` 隐式换算文案。
- 趋势图把 `kW`、`℃`、`-` 混在同一图同一纵轴展示，且无单位标签，存在误导风险（见 P0-03）。

## 2) 风险条目（P0/P1）

| 风险ID | 级别 | 风险描述 | 误判后果 | 证据点 |
| --- | --- | --- | --- | --- |
| P0-01 | P0 | `今日累计电量` 可能对应累计电能而非“当日累计” | 用户误判节能效果/日内变化 | 字典对 `totalElectricity` 的口径风险说明（`station_total_energy_kwh.note`） |
| P0-02 | P0 | `当前异常数` 实际来源是告警流计数，且单位用“项” | 异常与告警混淆，告警治理优先级判断偏差 | 前端取值 `anomaly.counts.total`，字段字典告警计数单位为“条” |
| P0-03 | P0 | 多序列趋势共用单纵轴，且未展示各序列单位 | 跨指标比较（COP/温差/功率）被错误解读 | 趋势面板当前仅显示数值，不显示单位与分轴 |
| P0-04 | P0 | stale 标识未覆盖所有关键展示（仅部分卡片/区域显式提示） | 用户把历史值当实时值 | 已有 banner/COP/趋势提示，但异常列表未显式跟随 stale |
| P1-01 | P1 | `当前 COP` 单位留空 | 文案规范不一致，阅读歧义 | 单位应为 `-`（无量纲） |
| P1-02 | P1 | “总站功率”措辞不够标准 | 字段语义弱化 | 建议与字典统一为“冷站实时总功率” |
| P1-03 | P1 | 未来多站点比较缺少前置条件提示 | 形成不可比结论 | 需加“比较前提”短提示（时间窗/采样/缺失策略一致） |

## 3) 修订建议（可直接交给前端替换）

### 3.1 直接替换文案（优先）

| 现文案 | 建议替换 | 触发/备注 |
| --- | --- | --- |
| `总站功率` | `冷站实时总功率` | KPI 标题直接替换。 |
| `今日累计电量` | `累计电能` | 默认替换；若已确认按日切片，再用“今日累计电能”。 |
| `当前异常数` | `当前告警事件数` | 与数据来源一致；单位同步改“条”。 |
| `异常总数：{n}` | `告警总数：{n}` | 异常看板中的回退文案同步。 |
| `高等级/中等级/低等级` | `高等级告警/中等级告警/低等级告警` | 降低与风险等级混淆。 |
| `当前 COP`（单位空） | `当前 COP`（单位 `-`） | 显示规范化。 |

### 3.2 趋势与单位文案（必须补）

| 现状 | 建议替换/新增 |
| --- | --- |
| 趋势图例只显示 `label + 最新/最小/最大`，不带单位 | 图例改为：`{label}（{unit}）`；示例：`冷冻水温差（℃）`、`冷站实时总功率（kW）`、`COP（-）` |
| 多指标混合同轴 | 在图标题或提示新增：`不同单位指标仅用于趋势观察，不做绝对值横向比较。` |

### 3.3 空值与陈旧状态文案（必须补）

| 场景 | 建议文案 |
| --- | --- |
| `value=null` 且 `return_null` | 展示 `--`，并在 tooltip 说明：`该指标当前缺失`。 |
| `freshness.stale=true` | 顶部统一提示：`数据陈旧（非实时）`；异常列表标题后缀追加：`（陈旧）`。 |
| 推荐规则跳过 | 保留现有 `RuleSkipDetails`，并在卡片区增加短句：`以下建议受缺失指标影响。` |

### 3.4 多站点比较前提短提示（建议新增）

建议固定提示文案（可放在比较入口或图表下方）：

`跨站点比较前提：时间窗、采样频率、缺失处理与错误分类口径一致；否则结论仅供参考。`
