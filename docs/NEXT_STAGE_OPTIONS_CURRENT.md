# NEXT_STAGE_OPTIONS_CURRENT

## 1. 目的

本文用于给当前阶段后的下一步选择做收口，避免项目再次进入“同时开太多线”的状态。

## 2. 选项列表

### 选项 A：进入 `/simulate` 治理预留

目标：

- 先定义 simulate 的职责边界、输入输出合同、未来仓库落点

优点：

- 延续 `/optimize` 治理思路
- 不会破坏当前主仓库稳定性

风险：

- 短期产出偏文档化
- 容易继续堆积“草案接口”，不一定带来真实产品前进

### 选项 B：进入 `/assistant/query` 治理预留

目标：

- 为站点助手查询接口预留合同和命名边界

优点：

- 有利于未来 AI 能力接入

风险：

- 当前业务价值不如 simulate 清晰
- 容易过早抽象

### 选项 C：做 2D/3D 深交互增强

目标：

- 在 `/scene-control` 之上继续做更深的节点级联动或页面双向跳转

优点：

- 用户感知强
- 现有 scene shell 已签收，有继续增强空间

风险：

- 容易进入重前端细节投入
- 收益不如扩展治理边界明确

### 选项 D：保留趋势历史问题复盘

目标：

- 将趋势历史问题材料整理为长期防回归参考

优点：

- 可保留历史证据链
- 不影响当前稳定盘面

风险：

- 不是直接产品增量
- 短期业务感知弱

## 3. 主控建议排序

1. 选项 D：保留趋势历史问题复盘
2. 选项 C：2D/3D 深交互增强
3. 选项 A：进入 `/simulate` 治理预留
4. 选项 B：`/assistant/query` 治理预留

## 4. 建议原因

当前最值得优先做的不是继续补迁页面，而是：

- 保持已签收页面稳定
- 只在明确批准后再开下一条扩展能力治理线
- 将趋势问题材料保留为防回归资产，而不是继续作为挂起主线

## 5. 当前主控建议

当前建议：

- 保持当前签收盘面稳定
- 若无明确批准，不进入任何 Phase 2 新能力实施
- 如确需继续扩展，先做趋势历史问题复盘与维护，再评审 `2D/3D` 深交互或 `/simulate` 治理预留
- 主仓库侧不再重新打开趋势开发线
