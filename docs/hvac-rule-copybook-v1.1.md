# HVAC 规则诊断文案二次收敛 v1.1（面向运维执行）

适用范围：
- 规则文件：`docs/hvac-rules-v1.yaml`（5 条规则，逻辑与阈值不变）
- 落点：`Recommendation` 建议卡、`RuleSkip` 跳过诊断区
- 目标：文案可执行、可验证、可回滚

版本信息：
- copybookVersion: `1.1.0`
- basedOn: `hvac-rule-copybook-v1@1.0.0`
- ruleSetRef: `hvac-rules-v1@1.0.1`

## 1) Recommendation 文案（每条规则 3 步执行建议）

### `low-delta-t-chilled-loop`（冷冻侧低温差）
- 一句话解释：在有一定负荷时，冷冻水温差持续偏低，通常表示换热利用不足或旁通偏大。
- 3步执行建议：
1. 先看指标：连续 15 分钟查看 `chilled_delta_t_c` 与 `station_total_power_kw`，确认是否稳定落入触发区间。  
2. 再做调参/检查：优先检查末端阀门与旁通支路；若需调参，冷冻供水设定每次只调整 `0.5°C`。  
3. 最后验证：观察 30 分钟，`chilled_delta_t_c` 回升且供冷舒适度无明显投诉，判定动作有效。

### `pump-frequency-too-high`（冷冻泵高频低效）
- 一句话解释：泵频长期偏高但温差提升有限，输配能耗可能偏高。
- 3步执行建议：
1. 先看指标：检查 `max_chilled_pump_freq_hz` 与 `chilled_delta_t_c` 的 20 分钟窗口趋势。  
2. 再做调参/检查：按 `2Hz` 级差逐步下调泵频，复核压差传感器与设定点漂移。  
3. 最后验证：连续 20 分钟内温差不恶化、压差与末端舒适度满足要求，即可保留新设定。

### `cooling-side-low-efficiency`（冷却侧效率偏低）
- 一句话解释：冷却侧功率投入较高但散热效果弱，系统 COP 被拖低。
- 3步执行建议：
1. 先看指标：同屏核对 `cooling_delta_t_c`、`cooling_tower_power_kw`、`station_cop` 连续 20 分钟表现。  
2. 再做调参/检查：优化塔风机分级与冷却水设定，设定温度单次调整不超过 `0.5°C`；并检查冷凝器结垢。  
3. 最后验证：1 小时内 COP 有提升、冷却侧温差不再持续偏低，且功率无异常上升。

### `frequent-start-stop`（设备频繁启停）
- 一句话解释：主机/水泵短时反复启停，存在控制震荡和设备损耗风险。
- 3步执行建议：
1. 先看指标：查看 `chiller_start_stop_count_60m`、`chilled_pump_start_stop_count_60m`、`cooling_pump_start_stop_count_60m`。  
2. 再做调参/检查：启用最小启停锁定（建议 `>=10 分钟`）并放宽控制死区；禁止连续人工强制启停。  
3. 最后验证：连续 2 小时启停次数回落至阈值以内，且告警事件不再新增。

### `stale-data-detection`（数据新鲜度不足）
- 一句话解释：关键输入数据滞后或缺失，建议可信度下降。
- 3步执行建议：
1. 先看指标：核对 `overview_data_age_min`、`anomalies_data_age_min`、`critical_metric_missing_count_5m`。  
2. 再做调参/检查：优先恢复采集链路与适配器；数据未恢复前禁止进行节能参数大幅调整。  
3. 最后验证：连续 30 分钟内数据时效恢复到阈值内，缺失计数稳定下降。

## 2) RuleSkip 文案（含排障顺序）

### `upstream_unreachable`
- 排障顺序（必须按序执行）：
1. 服务检查：确认 BFF/legacy 进程存活、健康检查返回正常。  
2. 网络检查：确认主机可达、路由和防火墙策略无阻断。  
3. 端口检查：确认 `8787/8098` 监听与接口连通。
- 模板：
1. 上游服务不可达，规则已跳过。请按“服务 -> 网络 -> 端口”顺序排障后重试。  
2. 当前链路中断，暂不输出诊断结论。先确认健康检查，再核对端口连通。  
3. 未获取到上游有效数据，规则执行暂停。建议优先恢复 BFF/legacy 可达性。

### `field_missing_or_invalid`
- 排障顺序（必须按序执行）：
1. 字段映射：确认规则字段与聚合字段一一对应。  
2. 单位口径：确认单位一致（如 `kW/kWh/°C`）且无混用。  
3. 采样有效性：确认采样周期、空值比例、时间戳连续性。
- 模板：
1. 关键字段缺失或无效，规则已跳过。请按“映射 -> 单位 -> 采样”顺序排查。  
2. 诊断输入不完整，暂不出结论。建议先修复字段映射与单位口径。  
3. 当前数据质量不满足规则执行条件，请先完成采样链路校验。

### `unknown`
- 排障顺序（必须按序执行）：
1. 版本一致性：确认规则版本与前端词典版本匹配。  
2. 词典收录：确认 `ruleId/skippedCategory` 已收录于 copybook。  
3. 合同一致性：确认 recommendations 合同字段未被破坏。
- 模板：
1. 未识别的跳过类型，系统已降级。请先核对版本与词典收录。  
2. 当前状态缺少映射模板，请检查规则版本和前端合同实现。  
3. 规则状态未知，建议按“版本 -> 词典 -> 合同”顺序完成核查。

## 3) 风险文案约束（统一规范）

### 风险映射（固定）
- `high` -> `高风险`
- `medium` -> `中风险`
- `low` -> `低风险`

### 严重度映射（固定）
- `critical` -> `紧急`
- `major` -> `重要`
- `minor` -> `提示`

### 语气与结构约束
- 高风险文案必须包含两项：
1. 优先级：明确写出 `优先级：P1`。  
2. 操作边界：明确写出可执行边界，例如“单次调参上限”“禁止动作”“复核窗口”。
- 中/低风险文案要求：
1. 使用“建议/请核查/纳入巡检”等中性语气。  
2. 禁止使用“立即停机/严重事故”等过度告警措辞（除非上游另有保护联锁信号）。

高风险模板示例：
- `优先级：P1。先做安全边界内的恢复动作，操作边界：单次调整不超过设定步长，完成后观察至少30分钟。`

中低风险模板示例：
- `建议在当班窗口内处理，按检查单逐项执行并记录验证结果。`

## 4) 前端接入建议（RuleSkip + Recommendation）

优先级：
1. 先本地词典映射（稳定输出中文可执行文案）。  
2. 再补 message 明细（拼接 evidence 与动作结果）。  

兜底文案：
- 未收录 `ruleId`：
  - 标题：`规则诊断（未命名）`
  - 说明：`该规则已触发，但当前版本暂无中文检查单。`
  - 建议：`请联系运维更新词典后再执行调参。`
- 未收录 `skippedCategory`：
  - `当前规则暂不可执行，系统已降级处理，请先核对版本与合同。`

## 5) 与 v1 差异节（新增/调整项）

新增：
- 每条规则新增“3步执行建议”（看指标 -> 做动作 -> 验证有效）。
- 每个 `skippedCategory` 新增“排障顺序”检查单。
- 增加高风险文案硬约束：必须带 `优先级` 与 `操作边界`。

调整：
- 将原“运维建议（短）”升级为可执行检查单格式。
- RuleSkip 模板从“提示型”收敛为“可执行排障顺序 + 模板”。

未变更：
- 规则逻辑、阈值、命中判定方式不变。
- recommendations 合同字段命名不变。
