# 冷站数字孪生建模

## 核心原则

- 以项目现有 Blender Python 生成器和源 `.blend` 为唯一真值源；不要把生成器或模型复制进 Skill。
- 优先使用后台 Blender 生成和校验。仅在必须操作 Blender 界面时加载 `computer-use` Skill，并在操作前告知用户。
- 不要保存或覆盖桌面 Blender 中带 `*` 的未保存会话。磁盘正式源文件必须由后台流水线产生。
- 保留用户现有脏工作区，不重置、不清理、不提交无关改动。
- 不把退出码、进程结束、单条日志、文件存在或 `ok=true` 当作完成；以最终 JSON 报告和视觉复查为准。
- Blender 即使发生Python异常也可能返回退出码0；运行器必须把 traceback、缺失/陈旧阶段报告或报告非 `PASS` 判为失败并立即停止。

## 执行工作流

1. 先读取 [references/plant-model-contract.md](references/plant-model-contract.md)，确认设备源、管路约束、验收计数和交付路径。
2. 检查用户参考图、当前 `git status`、模型清单、源 Blend、生成器、验证器及现有报告。使用 `view_image` 查看参考图和预览图。
3. 根据请求选择最小修改面：
   - 单设备修改：同时维护对应生成器、GLB回导验证器和设备端口元数据。
   - 压差变送器：采用无品牌湿-湿通用结构，H/L两个过程口保持54 mm中心距、同Y/Z坐标和独立字母+颜色识别；端面误差不超过5 mm、轴线夹角不超过2°。只登记2个过程口和1个合并电源/信号电缆口，不建三阀组、五阀组、均压阀、外接引压管或任何可写操作入口；无正常连续运动机构，内嵌动画对象/轨道必须为0/0。
   - 总览或管路修改：维护总览生成器及回导验证器；保持组件源 Blend 不变，除非用户明确要求修改组件。
   - 拓扑或数量修改：同步更新生成报告、回导验证、最终审计和工程合同，禁止只放宽测试。
4. 按真实曲线中心线放置软接、流量计和温压测点。Bezier 路线必须按曲线采样吸附附件，不能只按控制点坐标摆放。
5. 从设备源模型继承端口局部坐标和法向。禁止在总览中凭外观重建端口或把所有端口法向统一为 `+Z`；集/分水器主口必须校验水平轴向，支口必须校验竖直轴向。
6. 同时校验接管端点位置、端口法向、实际曲线端部切线和可见法兰面。端点及端口到真实法兰面的误差都必须不超过5 mm，轴线夹角必须不超过2°；集/分水器竖直接管在转向前保留至少300 mm直管颈。拆分集/分水器原型时不得把源模型 `Y=-0.38/+0.38 m` 的设备偏移二次归零，否则即使节点重合也会造成法兰视觉错位。
7. 保持管路工程约束：设备进出水成对水平布置、同系统接口同侧、尽量减少90度弯头、需要转向时优先顺水弯或135度路线、集水器和分水器管路分开且不堆叠。设备侧接管保持水平，只有进入干管过渡区后才允许变标高。
8. 布置多风扇冷却塔时，把同一塔组的风扇单元沿世界 `X` 轴排列，把不同塔组沿世界 `Y` 轴分组；同时校验每组单元的 `Y` 坐标一致，禁止只改标签或组号。
9. 水泵吸、排水工艺管只允许从真实泵口进入设备包络。与该泵无连接关系的工艺管、辅助管和控制管不得从泵轴、联轴器、电机或泵壳的上方、下方或内部投影穿越；必须在设备接口区外抬升或转向，以135度顺水段绕开完整可见泵体包络，管外表面净距至少300 mm。源 Blend 按真实Bezier中心线检查，GLB和LOD回导后按导出网格实体独立复算，禁止只信源报告字段。
10. 动画必须使用源设备的实际可动部件或独立工艺动画层，采用可循环的变换关键帧并随GLB/LOD导出；当前B25正式总览包含33个冷却塔风机转子、14根带非对称高对比指示片的水泵轴、8个冷冻水负荷侧流向短光段和8个四类主管短光段。水泵旋转指示片必须作为动画轴子节点随轴转动，并置于静止联轴器防护罩外侧的数字孪生动画层；禁止让安全防护罩旋转，也不能只做静态贴片。水流动画必须沿真实Bezier中心线采样，短光段贴近管外表面并沿切线旋转，禁止使用套在管外的圆环/光环；冷冻供回水、冷却供回水主管每类至少2个可见短光段。若项目包含Three.js运行时，使用沿管道连续滚动的箭头纹理，并预留 `flowM3h`、`flowDirection`、`flowActive` 驱动速度、方向和启停状态。渲染脚本必须逐帧调用 `scene.frame_set`，禁止只转相机却不计算设备动画。GLB回导后必须确认63个动画对象、63条动画轨道、16个中心线短光段、0个旧式水流光环和14个水泵旋转标记仍存在。
11. 检查独立工艺管实体净距。除明确登记的三通、汇流点或设备接口外，任何两根管不得实体相交；按实际中心线距离减去两管半径计算净距，当前模型交叉风险对必须至少保留20 mm。
12. 使用运行器完成交付：

```bash
python3 .agents/skills/blender-chilled-water-plant/scripts/run_pipeline.py --mode full
```

可选模式：

- `--mode validate-only`：执行GLB回导和最终资产验收，不重建模型。
- `--mode render-only`：重渲染24帧环绕图并生成GIF。
- `--dry-run`：只检查输入、冲突和计划执行的命令，不写模型或汇总文件。
- `--workspace /absolute/project/path`：指定同结构的智慧冷冻站工作区。

13. 运行后读取运行器给出的带时间戳汇总 JSON，并继续核对其引用的源生成、GLB回导、LOD、环绕渲染和最终审计报告。
14. 对预览图以及环绕帧 `000`、`006`、`012`、`018` 做视觉检查，确认无断管、漂浮附件、接口错位、管线实体交叉、管线堆叠、标签遮挡和意外品牌标识；动画项目还要确认风机、泵轴高对比标记、负荷侧与四类主管的表面短光段在不同帧中发生预期位移，且没有套管光环、穿管或明显偏离中心线。
15. 修改Three.js水流表现时，同步维护 `SystemDiagram3D.tsx`、`systemDiagramTypes.ts` 和 `check-auto-twin-ui-contract.js`；修改B25整站运行动画、设备运行状态、关键参数交互或默认相机构图时，还要同步 `PlantOverview3D.tsx`、`PlantOverview3D.css`、`SceneControlPage.tsx`、`SceneControlExtracted.css`、`check-auto-twin-ui-contract.js`、`check-operational-truth-ui-contract.js`、B25绑定合同和 `B25_RUNTIME_POINT_EVIDENCE_CONTRACT.md`。设备本体状态色只能使用运行时克隆的选择性PBR轻着色，禁止烘焙或永久覆盖共享GLB材质。状态表达默认采用精简方案：场景内常驻主机悬浮状态铭牌和选中详情卡数量固定为0；保留54台设备的本体轻着色、底座灯带/角框和始终可见的非颜色五态图形；顶部固定显示按CH1至CH7排序的精简“图形+设备号”状态条。全站关键工艺数据只显示7个沿主管真实世界坐标投影的锚点，悬停设备只显示该设备1项核心参数，点击设备打开宽360px的非模态只读右侧检查器，移动端改为底部抽屉；检查器只能有运行概况、趋势、告警诊断和设备档案，不得出现控制标签、启停、复位或频率设定。模型画布随侧栏缩窄并重新拟合，点击模型空白、关闭按钮或ESC必须清除选择。设备参数只能按合同身份及唯一 `deviceId + tagName` 读取，禁止用同组设备或全站汇总回填；每个值独立显示 `LIVE/SHADOW/STALE/UNBOUND`，无权威 `observedAt/changedAt` 时显示“时效不可证/--”。宽屏默认相机必须与两行紧凑HUD联合验收；当前B25参考方向向量为 `[18,22,34]`，画面按塔群左置、主机与水泵居中、集分水器右置构图，初始距离系数0.925、视觉中心上移约48px。完整设备和外接管不得裁切或被HUD/侧栏遮挡，CH1最上/CH7最下、泵轴与塔风机动画可辨；中等宽高比上移约12px，移动端保持保守无裁切距离且不做纵向偏移，用户旋转后的视角在响应式重排时不得被覆盖。运行 `npm run verify`，再用已有登录态的真实浏览器切换到三维场景，确认WebGL画面持续更新、54个状态标记、54项本体着色目标、129个涂装材质槽、0个常驻主机浮牌、7项精简主机状态条、7个工艺锚点、悬停单值、最多1个只读侧栏、0个控制标签、空白/ESC清除及五类计数一致且控制台无错误；无登录态时明确阻断实机视觉验收，不用构建成功冒充浏览器验收。
16. 制作对应2D水力图时，交互式2D与3D必须共用同一设备运行态与参数解析器；业务五态、参数和机械动画都按合同内唯一 `deviceId + tagName` 精确读取，禁止使用 `runtimeSummary.groups`、同组平均、页面摘要、模糊名称或数组顺序回填。设备必须同时显示颜色和运行`▶`、故障`▲!`、待机`Ⅱ`、停机`■`、未知`?`非颜色符号；参数无值显示`--/UNBOUND`，有值但缺权威时间显示`STALE/SHADOW·时效不可证`。点击2D设备打开与3D共用的只读参数侧栏，不得增加启停、复位或设频入口。交互式2D与3D还必须共用同一流量状态解析器，不得各自解释方向和启停；独立静态SVG交付只输出只读绑定合同并以全`UNBOUND`安全起步，不得声称文件本身已接入运行时。SVG管线使用静态基线加沿路径移动的短光段；正向箭头放在终点，反向箭头放在起点，停流时暂停短光段并降亮。对外暴露 `data-flow-evidence`、`data-flow-direction`、`data-flow-active` 供验收读取；无实时流量时标记为示意流向，禁止用泵状态推断水流。B25“运行监控-冷冻站”的2D入口固定优先加载本地 `/models/plant-overview/2d/chilled-water-plant-overview-latest-v2.svg`，不得被项目接口返回的旧远程2D地址覆盖；页面必须暴露 `physical-scada-2.5d`、`runtime-read-only-exact`、`exact-deviceid-tagname-read-only`、`schematic` 和无BA/PLC写入边界。该1920×1080资产默认按完整画布等比居中拟合，标题、六组塔、七套泵机组、集分水器、四个负荷闭环和底部图例均不得裁切；禁止沿用2500×920远程场景裁切窗口。
17. 独立2D交付默认采用“实物设备渲染 + 工程管线”的 `physical-scada-2.5d` 风格。主机、水泵和冷却塔必须从正式源 Blend 后台重渲染为透明RGBA、正交相机、统一灯光的专用PNG；SVG以 `xMidYMid meet` 嵌入，禁止复用带黑色摄影棚背景的旧预览、禁止裁切式 `slice`，并核对源 Blend、透明PNG和渲染报告三组SHA-256。
18. 2D设备接口必须由正式 Blender 端口元数据驱动。每个锚点至少写入 `data-source-port-id`、语义角色、源坐标、法向、DN和安装投影方式；当前B25正式总览必须有132个工艺端口锚点（28个主机、28个水泵、66个冷却塔、10个集分水器），每条工艺边端点到锚点误差不超过1px。水泵吸排口在安装态二维投影中保持同一水平中心线；主机两套水路继续校验源模型成对同标高。
19. 集水器和分水器在2D中保持同一纵向轴线、上下分开放置；分水器主入口在顶部、01至04支口从上到下，集水器01至04支口从上到下、主出口在底部。同编号分/集水器支口必须连接同一个唯一负荷节点，每个负荷恰好一条供水边和一条回水边，形成4个独立闭环，禁止重复负荷ID或把供回水画成两个无关联列表。支管走独立通道，不得堆叠；未登记供回水交叉必须为0。平面拓扑无法避免的跨越只能使用带断口的SCADA非连接桥，并登记 `data-connected=false`、上下管段ID和坐标，禁止直接十字相交冒充三通。
20. 2D运行数据采用只读证据四态 `LIVE/STALE/FAULT/UNBOUND`。`LIVE` 必须同时具备有限值、相关数据源健康和未超阈值的权威现场时间；只有显式设备故障位可标 `FAULT`，链路降级或请求失败不得冒充故障；有值但没有可信现场时间标 `STALE`；无有限值或无权威映射标 `UNBOUND`。无实时证据的温度、压力、流量、频率和负荷率一律显示 `--`，不得复制参考图数值。SVG、点位合同、端口合同和PNG来源证明必须相互校验，禁止旧PNG配新SVG仍判 `PASS`。
21. 单点权威 `observedAt` 必须在数据源明确确认本次观测、经现场验收的OPC UA DataValue确认当前值，或NTP/PTP对时的边缘采集器成功读点时产生，并由BFF透传。时间、质量和防重放三元组只能由服务端代码登记、与站点+适配器+接口+基址+项目键精确绑定的 `evidenceProfileId` 解码；payload内自报的 `sourceProtocol`、`timestampBasis`、`timestampRole`、`qualityCode=GOOD`或`statusCode=0`不得选择或绕过profile。未登记profile时必须输出 `observedAt=null`、`qualityCode=UNKNOWN/BAD` 且防重放三元组为null。PLC/OPC UA `sourceTimestamp`通常是值或状态最后变化时间，只能保存为`changedAt`；`generatedAt`、BFF抓取时间、HTTP返回时间、页面刷新时间以及B25数值型 `tagTime` 均不得冒充 `observedAt`。每个LIVE动画驱动点必须同时携带唯一点键、`qualityCode`、权威 `timestampBasis`、来源键、`sourceSequence`、`scanCycleId`和`bootId`，并跨轮询拒绝时间/序号倒退、同序号冲突及退役boot A→B→A复用；水泵与风机的运行和0至60 Hz频率反馈还必须来自同一 `bootId + scanCycleId`。水流动画独立校验流量证据；派生量取参与点中最早的 `observedAt`。质量为 `GOOD`、来源唯一健康且非fallback、未来偏差不超过2秒、点龄不超过20秒才可进入 `LIVE`；这两个时限是不可放宽上限，`maxFutureSkewMs=0`表示严格禁止未来时间。最终审计至少连续取两个快照验证单调性，单快照不得PASS。LIVE证据不合格时，可进入显式 `SHADOW`：只按合同内精确唯一的运行/频率值、健康非fallback来源和不超过30秒的 `receivedAt`收包TTL驱动泵轴与塔风机，证据仍保持STALE，水流保持暂停，不计入LIVE覆盖率或审计PASS；`receivedAt`不得冒充`observedAt`。SHADOW水泵/风机的运行位与频率点必须各自的 `receivedAt` 都精确等于同一顶层 `pointEvidence.receivedAt`收包快照；两点的 `bootId/scanCycleId` 只要任一字段出现，四个字段就必须成对完整且分别精确相同，部分携带必须拒绝；LIVE仍无条件强制完整且同一的 `bootId + scanCycleId`。来源异常、收包超时或点位不合格时暂停对应动画。显式 `DEMO` 可播放资产示意动画，但不得改变运行证据状态。
22. B25点表码与旧实时传输标签之间只允许使用绑定合同登记的精确别名：将点表码最前面的 `SY-` 替换为该设备 `{runtimeId}-`，再按 `deviceId + tagName` 精确且唯一匹配。禁止后缀匹配、模糊包含、中文名或数组顺序匹配。运行时证据审计必须核对54项设备身份、101个机械动画选择器（54运行+47频率）、162个业务状态选择器（54运行+54故障+54远程）、去重后的209个运行时选择器以及缺失清单；任一必需选择器未暴露、重复或证据不合格，都不得宣布运行态 `PASS`。
23. B25的 `visualization_only_no_ba_plc_write` 必须由后端和前端双重执行，并同时约束LIVE、SHADOW、DEMO三种展示模式：公开B25 `/scene/device-command` 无条件返回403且不得进入全局只读写白名单；真正调用BA适配器的 `submitSceneDeviceCommand` 服务还必须对B25所有别名和任何调用入口做上游请求前硬阻断，确保包括FCU编排在内的旁路也是上游请求0次。前端在整个B25项目范围内禁用控制，不得只在3D模式阻断。审计顶层状态必须包含控制边界，不能出现控制或流量证据检查失败但总状态仍为 `PASS`。
24. B25设备业务状态、点位证据状态和动画模式必须作为三层独立合同：业务状态为 `RUNNING/FAULT/STOPPED/STANDBY/UNKNOWN`，证据层为 `LIVE/SHADOW/STALE/UNBOUND`，动画层为 `LIVE/SHADOW/DEMO/PAUSED`。业务状态只能按绑定合同中的 `deviceId + tagName` 精确唯一读取54个运行位、54个显式故障位和54个远程位；频率另有47项，总计162个状态选择器、209个唯一运行时选择器。三类状态位只接受原始布尔值、数值0/1或字符串`"0"/"1"`，禁止trim后接受文本状态。显式故障位为1时故障优先；无故障且运行位为1才是运行；无故障、停机且远程为1是待机，远程为0是停机。缺点、重复点、BAD、来源异常、收包超时、值冲突或值非法一律降级为 `UNKNOWN`，禁止从 `runtimeSummary.groups`、中文语义、模糊包含、后缀或数组顺序推断。SHADOW可显示精确显式故障信号但必须标注“时效不可证”，不得提升LIVE、不得驱动水流或计入权威验收；通信故障不得冒充设备故障。机械动画只有在业务状态为RUNNING且独立运行/频率动画证据合格时启用；FAULT、STANDBY、STOPPED和UNKNOWN均停止机械运行时动画，显式DEMO仍只作为不改变业务状态的资产示意。LOD0/LOD1/LOD2各保持同一54项设备状态映射；状态颜色只由Three.js运行时标记层表达，不得烘焙进源Blend/GLB或永久覆盖共享PBR材质。颜色之外必须同时提供中文文本或形状，推荐运行绿、故障红、待机琥珀、停机灰、未知灰蓝，SHADOW使用空心或虚线区分。LIVE、SHADOW、DEMO和所有业务状态均继续保持GET-only、无BA/PLC写入。
25. B25设备状态的三维主表达使用贴近设备底部包络的状态灯带和四角定位框，悬浮圆圈只能作为选中定位辅助手段，不得继续作为唯一主表达。五类状态除颜色外还必须具有稳定形状语义；SHADOW使用空心、分段或虚线结构，并继续显示“时效不可证”。只有 `FAULT` 状态允许慢速脉动，RUNNING、STANDBY、STOPPED和UNKNOWN的状态层必须静止，设备机械运动仍服从第24条门禁。状态筛选只能降低未匹配设备的显示亮度，不得隐藏设备、改写业务状态、改变五类计数或影响动画证据；提供上一异常/下一异常导航，且不得借此增加确认、复位或控制动作。LOD0/LOD1/LOD2只允许做语义缩放：三级中54台设备的RUNNING、FAULT、STANDBY、STOPPED、UNKNOWN非颜色形状徽标必须始终存在且可见，只能调整缩放、线宽和非选中文字，不得隐藏RUNNING/STANDBY/STOPPED字形或根据状态删减徽标。设备业务状态、告警生命周期和诊断提示必须使用独立字段及DOM属性：诊断矛盾不得改写业务状态，显式故障位也不得冒充告警已确认或已闭环。当前没有权威状态变更时间时，右侧只读检查器的状态持续固定显示`--`和“无权威 changedAt”，同时根节点暴露 `data-selected-equipment-status-duration="unavailable"` 与 `data-selected-equipment-status-duration-basis="missing-authoritative-changed-at"`；禁止用页面会话起点、`receivedAt`、`generatedAt`、刷新时间或当前时间推算状态持续时长。根节点还要暴露视觉版本、筛选值与匹配数、计数不变性、异常导航、LOD语义缩放、7个工艺锚点和悬停单值合同，浏览器验收必须逐项读取这些属性。鼠标悬停拾取只能对54个独立轻量状态标记代理做射线相交，并用 `requestAnimationFrame` 将高频 `pointermove` 合并为每帧最多一次；禁止在 `pointermove` 递归射线检测整个高面数GLB模型。

## B25只读绑定边界

- B25正式几何清单为7台主机、7台冷冻水泵、7台冷却水泵、6组冷却塔，各组风机数为 `[6,6,6,6,6,3]`，共65个设备实例。核心B25设备绑定为54项（7主机+14水泵+33风机），仅允许显式 `equipmentId/runtimeId/deviceIdRef` 映射，禁止按顺序或名称猜测。
- 绑定合同必须保持 `authoritative=false`、`authority.identity=true`、`authority.telemetry=false`、`authority.geometryTopology=false`和 `visualization_only_no_ba_plc_write`。设备身份映射可确认，但现有几何管路仍是工艺模板，不得声称为B25权威P&ID或现场管网真值。
- 只读摘要缺少可权威证明的逐点现场时间时，有限值只能标 `STALE/时效不可证`，空值标 `UNBOUND`；禁止因接口请求时间或页面刷新时间将其升级为 `LIVE`。可使用明确标记的 `SHADOW` 机械动画按精确唯一运行/频率值启停调速，也可按精确显式运行/故障/远程点显示带“时效不可证”标识的业务状态，但收包TTL不得超过30秒，水流必须暂停，且不得计入LIVE/验收PASS或产生BA、PLC、阀门、变频器写入。缺少任一业务状态必要点时显示 `UNKNOWN`，不得猜成停机、待机或故障。
